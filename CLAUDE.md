## Project Overview

This is an HSF (HEP Software Foundation) training lesson website teaching SSH (Secure Shell). It's built using **Jupyter Book** - a static site generator built on top of Sphinx. The site is published on GitHub Pages.

**Previous Version**: This repository was previously built with Jekyll and the Carpentries template. It has been migrated to Jupyter Book. Old Jekyll files are archived in `_jekyll_archive/` for reference.

## Architecture

### Jupyter Book Structure
- **Framework**: Jupyter Book (Python-based static site generator using Sphinx)
- **Markdown Format**: MyST (Markedly Structured Text) - an extended Markdown syntax
- **Theme**: Sphinx Book Theme (configured in `_config.yml`)
- **Main Branch**: `jupyterbook` (for development and deployment)
- **Publishing Branch**: `gh-pages` (auto-generated by GitHub Actions)

### Content Organization
- **Landing Page**: `intro.md` - main introduction and prerequisites
- **Chapters**: Numbered markdown files in root directory:
  - `01-introduction.md` - Introduction to SSH and asymmetric encryption
  - `02-basics.md` - Basic SSH commands and file copying
  - `03-nested.md` - Nested SSH connections (optional)
  - `04-config.md` - SSH configuration file
  - `05-keys.md` - Key-based authentication
  - `07-port-forwarding.md` - Port forwarding and tunneling
  - `08-tips.md` - Additional tips (rsync, tmux, etc.)
- **Supplementary Pages**: `setup.md`, `reference.md`
- **Configuration**: `_config.yml` (Jupyter Book settings), `_toc.yml` (table of contents)
- **Images**: `fig/` directory
- **Archived Jekyll Files**: `_jekyll_archive/` (old `_episodes/`, `_extras/`, `_includes/`, Gemfile, Makefile)

### Dependencies
- Python 3.11+
- Jupyter Book >= 0.15.0
- Sphinx >= 5.0
- Sphinx Book Theme >= 1.0.0
- MyST Parser >= 1.0.0

## Common Commands

### Building the Book
```bash
# Install dependencies
pip install -r requirements.txt

# Build the book
jupyter-book build .

# Clean previous builds
jupyter-book clean .

# Rebuild from scratch
jupyter-book clean . && jupyter-book build .
```

### Local Preview
```bash
# After building, serve locally
cd _build/html
python -m http.server 8000
# Then open http://localhost:8000 in browser
```

### Pre-commit Hooks
```bash
# Install pre-commit
pip3 install pre-commit
pre-commit install

# Run manually
pre-commit run --all-files
```

Pre-commit hooks check for:
- Large files
- Merge conflicts
- Trailing whitespace
- End-of-file fixes
- Spelling errors (codespell with custom dictionary in `codespell.txt`)

## Content Writing Guidelines

### MyST Markdown Syntax

Jupyter Book uses MyST (Markedly Structured Text), an extended Markdown format. Key features:

**Admonitions** (callout boxes):
```markdown
```{note}
This is a note.
```

```{warning}
This is a warning.
```

```{danger}
This is a critical warning.
```

```{admonition} Custom Title
:class: tip
This is a custom admonition styled as a tip.
```

**Dropdowns** (collapsible content):
```markdown
```{dropdown} Click to expand
Hidden content here.
```
```

**Figures**:
```markdown
```{figure} fig/image.png
---
name: figure-label
---
Caption text here.
```
```

**Code blocks**:
````markdown
```bash
command here
```
````

**Exercises** (use custom admonitions):
````markdown
```{admonition} Exercise
:class: tip
Exercise text here.
```
````

### Content Structure Guidelines

1. **Chapter Files**: Each chapter should have:
   - A level-1 heading (`#`) for the title
   - Learning objectives in an admonition at the start
   - Key points in an admonition at the end
   - Proper section headings (`##`, `###`)

2. **Images**: Reference images relative to root: `fig/image.png`

3. **Internal Links**: Use standard markdown links or MyST cross-references

4. **Avoid**:
   - Jekyll-specific syntax (`{% %}`, `{{ }}`)
   - Carpentries-specific callouts (`{: .callout}`, `{: .challenge}`)
   - Liquid templating

## Deployment

### GitHub Actions Workflow

The book is automatically built and deployed via `.github/workflows/deploy.yml`:
- **Trigger**: Push or PR to `jupyterbook` branch
- **Build**: Installs dependencies, runs `jupyter-book build .`
- **Deploy**: Publishes `_build/html/` to `gh-pages` branch (on push to `jupyterbook`)
- **URL**: https://hsf-training.github.io/hsf-training-ssh-webpage/

### Manual Deployment

If needed, you can deploy manually:
```bash
# Build the book
jupyter-book build .

# Install ghp-import if needed
pip install ghp-import

# Deploy to gh-pages branch
ghp-import -n -p -f _build/html
```

## Configuration Files

### `_config.yml`
Main Jupyter Book configuration:
- Book metadata (title, author, copyright)
- Repository settings
- HTML theme options
- Sphinx configuration
- MyST parser extensions

### `_toc.yml`
Table of contents defining book structure:
- `root`: Landing page (intro.md)
- `chapters`: List of chapter files in order
- Each entry has `file` (without .md) and optional `title`

## Development Tips

1. **Always rebuild after changes**: Jupyter Book doesn't auto-reload like Jekyll. Run `jupyter-book build .` to see changes.

2. **Check for warnings**: Jupyter Book shows warnings during build. Fix them to ensure proper rendering.

3. **Test locally before pushing**: Build and preview locally to catch issues early.

4. **MyST syntax**: When in doubt, check the [MyST documentation](https://myst-parser.readthedocs.io/) or [Jupyter Book docs](https://jupyterbook.org/).

5. **Images**: Ensure images exist in `fig/` and paths are correct relative to root.

6. **Table of Contents**: If adding/removing chapters, update `_toc.yml`.

## Migration Notes (Jekyll → Jupyter Book)

Key differences from the old Jekyll setup:
- **No `_episodes/` directory**: Chapters are now in root as numbered files
- **No `_config.yml` for Jekyll**: New `_config.yml` is for Jupyter Book (completely different format)
- **No Liquid templating**: Use MyST syntax instead
- **No `bundle exec jekyll serve`**: Use `jupyter-book build .` instead
- **Callouts changed**: `{: .callout}` → `{note}`, `{: .challenge}` → `{admonition}`, etc.
- **Branch**: Development on `jupyterbook` branch (not `gh-pages`)

## Troubleshooting

**Build fails with "unknown directive"**: Check MyST syntax, ensure proper backticks and indentation in admonitions.

**Images not showing**: Verify image path relative to repository root, ensure file exists in `fig/`.

**Table of contents doesn't update**: Ensure `_toc.yml` has correct file names (without .md extension) and proper YAML syntax.

**Deployment not working**: Check GitHub Actions logs, ensure workflow has proper permissions to deploy to `gh-pages`.
